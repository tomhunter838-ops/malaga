The streams

Working rules

How to update a stream

  1. Open that stream's thread in Cowork and say what happened, in one message.
  2. The thread updates its own folder and the shared memory in the same session, and tells you what other streams need to re-read.
  3. Never edit 40_Current_2026-09\ — new facts go in new dated files.
  4. Every email that matters is forwarded to Prana Outlook and filed in Correspondence\ with a register row.
  5. Ask the thread for a tracker delta (JSON) when tasks change — see Update from JSON below.

How handoffs and new threads work

  1. To pass work across: the giving thread writes a numbered handoff file into the folder root (next number) and updates memory.
  2. Open the receiving thread and type "Read root file <n> and update the plan."
  3. To start a new stream: ask the current thread for a handoff file, create a new thread in the same Cowork project, paste the file as the first message.
  4. When a thread's context gets long, ask it for a fresh handoff and continue in a new thread with the same name.
  5. Nothing is sent, paid or submitted by any thread. Hola (the Grok manager) reads the folder when told and writes nothing.

Tools for Claude and the threads

Ask any thread: "Give me a tracker delta JSON for what changed, in the schema on the plan page." The schema:


      
Fields: id short, stable, letters and digits only (ticks are keyed on it — never rename an id, retire it and add a new one) · track one of the workstreams · owner tom / chelsea / both / adviser / driver · t title · next what to do · d comfortable date (ISO) · ls last-safe date (optional) · hard true for a binary gate · quick true for an under-30-minute job. Updates only need the id and the fields that change.

      
Precedence: the newest issued wins. A published plan overrides the GitHub copy until Claude bakes a newer plan.js.
